# X built-in Grok (local development)

Select **Settings → Connection → X built-in Grok** and save. Stay signed in to X in the same browser profile. This mode needs no API Key, subscription OAuth or local Build service.

SuperX initializes X’s Grok connection using an offscreen, inert floating panel in the current page. It then sends its own independent session and request over a dedicated authenticated WebSocket, explicitly selecting **Fast**. It reads original Markdown deltas directly into the shared safe Markdown renderer. Citation URLs arrive as separate API metadata and become clickable numbered superscripts. It does not copy rendered answer DOM, use the clipboard, write the native editor, or click New Chat/Send/Stop. It calls X’s existing native credential function and WebSocket authentication adapter in the page MAIN world; authentication material stays in page memory and is never sent to the extension background, logs or files. It creates no task tabs, windows or frames and performs no navigation.

Up to 10 native checks can run concurrently across the extension. Panel initialization is serialized within a page; after the API starts independently, its owned panel closes and the next request can initialize. Each request keeps its slot until terminal acknowledgement and actual socket closure. An already-open user Grok panel is left untouched. Existing drafts or active native generation prevent submission. On user takeover SuperX releases its hidden panel and cancels only its own response. The native visible conversation is preserved. Initialization handoff collapses only the owned panel and restores reading-page focus/caret. Later results never touch a newer native panel.

The instructions contain the original published-post URL and bounded visible context. Requests consume the account’s web allowance and can be retained by X/Grok. There are no token counts or unlimited-usage guarantees. Draft checks and comment generation are unsupported. Media URLs are context rather than uploaded native image inputs; retrieval must happen before claiming inspection.

Automatic triggering and dwell settings still apply. Scrolling away withdraws unstarted work; started checks continue. Pause, source changes, navigation and source disconnection request cancellation. Cancellation uses the API’s response.cancel for SuperX’s own response and waits for matching response.done or actual socket closure before releasing the request slot. Unconfirmed cancellation blocks new checks; a late acknowledgement can clear that gate. An unclassified API rejection or unavailable authenticated connection pauses automatic checks until connection settings are saved again, since it may represent account restrictions. There is no automatic replay. An unacknowledged cancellation closes only the dedicated socket and waits for its real close event; this confirms local disconnection, not provider-side billing or computation termination. Partial, failed, empty or oversized replies are not reported as successful. Invalid citation metadata fails explicitly.

The private protocol observed on 2026-10-26 uses wss://grok.com/ws/mgw/. The fixed gateway URL requires the native uid query parameter; credentials and this account value never cross the page bridge. A fresh session.create is correlated by client_event_id; conversation.attached precedes one response.create; response.created binds the response ID. Only matching session/response assistant-channel deltas and citation metadata enter the answer. Empty output_text.done fields do not replace streamed text. Only response.done with completed status marks success. Reasoning, tool output and other sessions are discarded. The observed React runtime and native webpack auth adapter are private, changeable dependencies; missing capabilities fail explicitly. This unofficial protocol may change.

Raw model HTML and remote images are not executed or loaded. Native answers are excluded from the shared answer cache, persistent local answer history and API diagnostics. Visible post visits follow the independent local history setting. Window bridge messages are routing, not a trusted proof of model claims; answers retain unverified metadata.

Use extension/ as an unpacked development installation. Disable duplicate copies to avoid duplicate requests. Reload the extension after edits, then refresh X. Source changes do not update a store installation or publish a release.

## Concurrency and Markdown follow-up

The previous single-request ceiling was an extension restriction. Native mode now has 10 independent request slots; this reduces multi-post queueing, not the provider’s latency for a single searched answer. A short-request prototype accepted 10 Fast sessions: 9 distinct answers and one deliberate cancellation; observed active-response peak was 8, so this does not establish 10 simultaneous server generation workers. After reload, the installed extension completed 12 Fast checks with zero request errors and an observed overlap peak of 7. The loaded panel code confirms the client cap of 10; the actual server worker count is not guaranteed. The installed renderer also produced proper strong nodes for adjacent Chinese/currency emphasis. Evidence: artifacts/x-native-acceptance-20261026/ten-installed-audit.json.

The renderer includes the MIT-licensed marked-cjk-friendly 0.1.3 tokenizer extension. It fixes CJK text adjacent to punctuation/symbol emphasis such as 约**$32**, without inserting spaces, rewriting the original Markdown or changing the safe DOM renderer. Upstream: https://github.com/tats-u/markdown-cjk-friendly.
